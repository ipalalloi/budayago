# Kompatibilitas, pengujian dan keamanan

**Lingkungan aktual.** Debian 13 (amd64), PHP CLI/built-in HTTP 8.4.24, PDO MySQL native prepares, mbstring, fileinfo, session, MariaDB 11.8.6/InnoDB, skema baru sck008_fixture dan sck008_restore; browser Chromium headless 150.0.7871.181. HTTP loopback dapat menguji service worker. VPS, MySQL 8 Oracle, FPM, Nginx dan HTTPS domain target memerlukan bukti terpisah. Asal paket memakai target PHP 8.2+, MySQL 8.0+/MariaDB 10.5+. Versi minimum tersebut belum semuanya diuji. Tidak ada dependency Composer untuk aplikasi.

**Hasil ulang.** Lihat evidence/php-lint.txt; unit.txt berisi 19 pemeriksaan policy, 8 private reference, 10 throttle dan 18 guard. Database baru menerima migrasi dasar, lalu dua migrasi aditif dan pengulangan kedua migrasi aditif. Foreign key ke aset yang tidak ada ditolak; daftar tabel, relasi dan indeks diperoleh dari information_schema. Schema fixture memiliki 12 tabel dan 20 foreign key. Uji HTTP memakai peran dan session terpisah dengan CSRF, SQL parameterized, file multipart dan byte media asli sintetis. Uji hak mengecek state DB setelah rollback, hasil galeri, response stream 200/206 dan penolakan 403. Dua skema restore membandingkan dump data terurut dan salinan media secara byte. Verifikasi browser terpisah dari penerimaan manusia. Pembatas autentikasi berbasis file SCK-007 cocok untuk single host; verifikasi perilaku alamat klien pada reverse proxy aktual.

**Pengulangan.** Jalankan tests/run_local_fixture.sh pada mesin Linux uji dengan MariaDB server/client/dump/install-db, PHP CLI dan ekstensi di atas, curl, ffmpeg, Python 3, Playwright dan Chromium. Set MARIADB_BASE dan BROWSER_BIN bila berbeda. Gunakan user non-root dan salinan source tanpa config.php. Runner memakai port loopback 33781 dan 18768 (keduanya harus kosong), direktori privat baru, kredensial acak, daemon sendiri, cek datadir dan menutup prosesnya. Bukti baru ditulis ke direktori kerja sementara yang dicetak. Direktori privat juga menampung DB/dump sintetis; bagikan hanya ringkasan evidence. Tes integrasi historis yang ditujukan khusus ke sck_ci tidak dipanggil. Di Windows jalankan persiapan ZIP, bukan runner Linux pada DB aktif.

**Media dan privasi.** Pembacaan oleh tamu membutuhkan record terbit, tiga izin, telaah kurator, flag publikasi serta grant media. Holder, pemilik, admin dan kurator mempunyai jalur privat sesuai fungsi. Kewenangan budaya perlu dibuktikan melalui dokumen dan telaah manusia. Referensi privat tidak memvalidasi keaslian dokumen secara otomatis. Izin publikasi tidak mencakup distribusi ulang, pendidikan atau pelatihan AI. Periksa persetujuan orang yang terdengar/terlihat, kebijakan komunitas, metadata lokasi, konten PDF dan redaksi sebelum upload ke koleksi yang akan dibuka. Unggah salinan publik yang telah ditelaah, simpan master berbeda sesuai hak. Penarikan menghentikan permintaan baru; pengunduhan terdahulu tidak dapat dibatalkan oleh server.

**Batas review.** Pemeriksaan internal menggunakan validasi MIME aktual, nama simpan acak, penyimpanan di luar web root, query terparameter, escape output, pengujian fungsional CSRF/session/RBAC serta penolakan tipe/ukuran. Antivirus/CDR, pemeriksaan seluruh format, timeout, lintasan TLS/proxy, concurrent load, uji koneksi DB terputus saat commit dan penilaian keamanan independen belum terpenuhi. Jangan isi galeri staging dengan budaya nyata. Jika commit DB memiliki hasil tidak pasti, periksa relasi kuitansi/audit dan inventaris media dengan cara read-only sebelum retry/pembersihan. Rujukan teknis untuk telaah operator tersedia pada [OWASP File Upload](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html).
